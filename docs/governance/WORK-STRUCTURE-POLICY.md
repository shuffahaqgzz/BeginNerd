# Adaptive Work Structure Brainstorming — Approved Addendum

**Owner:** PLANNING-02. Supporting workflows: PLANNING-01, PLANNING-03 and PLANNING-04. IMPLEMENTATION-01–05 consume its approved formal task contracts.

## Proportional planning
1. Explain only the hierarchy concepts relevant to the project: release, milestone, epic, work package, task, optional subtask.
2. Compare Lean, Structured and Extended approaches; no mandatory hierarchy levels.
3. Consider approved scope, acceptance, dependencies, capacity, risk, and vertical-slice opportunities.
4. Recommend the smallest sufficient formal work breakdown.
5. Obtain explicit Owner approval when the formal scope, acceptance or material dependencies are chosen or changed.
6. Preserve stable task IDs, acceptance, dependencies, owner, approval and historical changes.

## During implementation: iterative, not waterfall
- **Allowed within an approved task:** technical investigation, changing an algorithm or implementation steps while preserving approved architecture and acceptance, adding internal checklist steps, running tests, and fixing small defects within existing batch authorization. These are not new formal subtasks; record them as execution evidence as appropriate.
- **Requires controlled replanning:** new formal task/package, meaningful change to product outcome, task scope, acceptance, approved technology/security architecture or dependency relationships. HOLD **only the affected work**, propose the impact and return to PLANNING-02 for review. Other authorized work can continue.
- **Never:** have an executor, coordinator or subagent quietly create formal issues/tasks and treat them as approved. Do not use a minor incidental technical step as an excuse for a full lifecycle restart.

Batch approval of approved tasks can cover routine work, but it is not blanket permission for unrelated source changes or external deployment.
