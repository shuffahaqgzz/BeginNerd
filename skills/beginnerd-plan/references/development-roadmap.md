# PLANNING-01 — Development Roadmap & Milestones

**Input:** Approved G1/G2 artifacts applicable to the scope, existing project state and authorized decisions.
## Procedure
1. Read approved Product MVP, Solution Design and user priority; identify value outcomes and prerequisites.
2. Distinguish RELEASE (usable version), MILESTONE (outcome achieved), DELIVERABLE (concrete artifact), ACCEPTANCE (observable verification).
3. Create outcome-driven milestones and release boundaries with explicit in/out/deferred scope, dependencies and risk.
4. Adapt solo/team capacity and target dates; do not invent precise timelines without evidence. Material dates require user approval.
5. Map milestone → approved requirements, expected deliverables, acceptance, dependent components and likely owner. Provide clear next milestone.

**Canonical output:** DEVELOPMENT-ROADMAP.md or Lean DEVELOPMENT-PLAN.md section.
**Completion criteria:** Every milestone has observable user outcome and linked acceptance; not a deployed release.
**Boundaries:** Do not claim task accepted or tests executed from drafting. Files/issues publishing require target-specific authorization and readback. If prerequisites fail, report PARTIAL/BLOCKED and restrict affected work.
