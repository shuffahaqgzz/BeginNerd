# SOLUTION-08 — UI Design & Design System / Adaptive Visual Review

**Input/trigger:** Approved journeys, device constraints, existing design tokens and accessibility needs. Run when this specific solution domain is requested; respect current G1 scope and approval.

## Procedure
1. Inventory reusable patterns/assets before selecting any design tooling.
2. Choose text review, low-fidelity or high-fidelity review by complexity and stakeholder need; no mandatory Figma/Penpot.
3. Describe information hierarchy, components, responsive behavior, form errors, keyboard/focus/labels and contrast.
4. Check UI against navigation, flows and role access; capture material feedback, decision and planned usability tests.
5. Link each material decision to source REQUIREMENTS / ACCEPTANCE IDs, evidence and timestamp where available; mark missing facts TBD and assign a decision owner.

**Canonical output:** UI-DESIGN.md or Lean section. Lean/Structured is adaptive; do not require every design document.
**Acceptance for this design workflow:** UI review is documented and consistent; not implemented or usability tested.
**Governance:** Explain → Interview → Approve → Record; write only within an authorized path. A planned verification is NOT EXECUTED. No formal task decomposition and no change of application runtime.
