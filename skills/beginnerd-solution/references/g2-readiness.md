# G2 — Solution Design Readiness (Phase 2)

Run only for user-requested G2 review or Phase 2 handoff. Assess each item with requirement/ID, source/evidence, owner, gaps and status:

1. Critical product requirements have appropriate solution design and unblocked approved scope.
2. User Flow, Application Navigation and UI/Design consistent including failure states.
3. Architecture/domain responsibility and data/trust boundaries clear.
4. Data/DB design addresses integrity, authorization and lifecycle.
5. API/integration contracts are testable, errors and dependency failures covered.
6. SOLUTION-06 research contains sources/dates, license, cost, security, maintenance, best-fit rationale and material approval.
7. Threats/controls/planned security tests address all critical security risks.
8. Material decisions are explicitly user-approved with evidence; no inferred consent.
9. Requirements → design → planned tests traceability and canonical artifacts agree.
10. Unknowns, risks, deferred items, affected scope and next owners are recorded.

**PASS:** all applicable criteria met with direct evidence, no critical blocker.
**PARTIAL:** useful design but unresolved gaps, plan only unblocked scope.
**BLOCKED:** material conflict/unmitigated critical risk, do not hand affected scope to implementation.
**UNVERIFIED:** individual absent evidence. No checklist or created documents alone constitute PASS.

G2 validates solution design; it is NOT an app security certification, code QA, deployment authorization or replacement of G1.
