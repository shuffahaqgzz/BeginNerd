# SOLUTION-02 — Application Flow & Navigation

**Input/trigger:** Approved user journeys, roles, existing routes and target devices. Run when this specific solution domain is requested; respect current G1 scope and approval.

## Procedure
1. Inventory screens/routes/menu and authorized entry points for MVP only.
2. Map screen transitions, loading/empty/error/unauthorized, back/deeplink behavior and expected feedback.
3. Check navigation loops and accessibility; hiding UI links is not backend authorization.
4. Review screen map with user, compare alternatives and record material approval.
5. Link each material decision to source REQUIREMENTS / ACCEPTANCE IDs, evidence and timestamp where available; mark missing facts TBD and assign a decision owner.

**Canonical output:** APPLICATION-FLOW.md or Lean section. Lean/Structured is adaptive; do not require every design document.
**Acceptance for this design workflow:** Critical user journey has consistent navigation; not a browser execution.
**Governance:** Explain → Interview → Approve → Record; write only within an authorized path. A planned verification is NOT EXECUTED. No formal task decomposition and no change of application runtime.
