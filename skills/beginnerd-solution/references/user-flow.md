# SOLUTION-01 — User Flow & Journey

**Input/trigger:** Product requirements, actors, channel, success criteria. Run when this specific solution domain is requested; respect current G1 scope and approval.

## Procedure
1. Identify real actor, trigger, preconditions and observable outcome; mark personas not supported as ASSUMED.
2. Model critical journey including happy, unauthorized, invalid data, empty and failure/recovery paths where relevant.
3. Map REQUIREMENTS IDs → flow steps → acceptance IDs; avoid introducing deferred features.
4. Use Adaptive Visual Review with minimal legible diagram or steps; explain options and ask material approval.
5. Link each material decision to source REQUIREMENTS / ACCEPTANCE IDs, evidence and timestamp where available; mark missing facts TBD and assign a decision owner.

**Canonical output:** USER-FLOW.md or Lean section. Lean/Structured is adaptive; do not require every design document.
**Acceptance for this design workflow:** Each critical journey mapped and reviewed; not an executed usability test.
**Governance:** Explain → Interview → Approve → Record; write only within an authorized path. A planned verification is NOT EXECUTED. No formal task decomposition and no change of application runtime.
